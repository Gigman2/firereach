# 192 as the Primary Toll-Free Dial Target — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `192` the primary number the app dials everywhere, with station hotlines demoted to clearly-labelled secondary actions that may cost airtime.

**Architecture:** `dialOrder` is replaced by `dialTargets`, which returns `{ phone, tollFree }` with `192` always first. The rename forces every call site to be revisited by the compiler rather than silently inheriting a reversed order. Screens use the `tollFree` flag to label cost honestly.

**Tech Stack:** Expo SDK 55, React Native 0.83, TypeScript 5.9, jest scoped to `src/lib`.

## Why this reverses a previous decision

Every seeded station number is a **chargeable hotline**. GNFS itself draws the line — *"Our emergency numbers (112/192) and hotlines (0302772446, 0299340383)"*. Only `192` is toll-free and connects with **zero airtime** on MTN, Telecel and AirtelTigo.

The app currently makes a chargeable hotline the primary button. A caller with no credit — plausible in an emergency, and disproportionately the rural users the Product Scope names as primary — taps the big red button and the call simply fails, while the one number that would have connected sits under "Other numbers".

This also settles the dial-target precedence question that was previously deferred. The earlier argument was about data provenance; the toll-free fact is stronger and points the same way.

`112` is dropped entirely. It is also toll-free and reaches the fire service, but it routes through national dispatch rather than being fire-specific, and one number is less to get wrong under stress.

```ts
export type DialTarget = {
  phone: string;
  /**
   * True only for 192. Toll-free numbers connect on any Ghanaian network with
   * no airtime; everything else in the chain is a chargeable landline that a
   * caller with no credit cannot reach at all.
   */
  tollFree: boolean;
};

/**
 * Numbers to offer, best first. 192 always leads and is always present.
 *
 * This is deliberately NOT ordered by which line is most likely to answer.
 * Every station number in the dataset is a chargeable hotline — GNFS itself
 * separates "emergency numbers (112/192)" from "hotlines" — and 192 is the
 * only one that connects with zero credit. Leading with a hotline means a
 * caller with no airtime taps the primary action and nothing happens.
 *
 * The hotlines that follow keep their source ordering, which reproduces the
 * publication order of a 2022 page and measures nothing. They are alternatives,
 * not a ranked likelihood of pickup.
 */
export function dialTargets(station: CachedStation): DialTarget[] {
  const hotlines = station.contacts
    .filter((c) => c.active && c.phone !== NATIONAL_EMERGENCY_PHONE)
    .slice()
    .sort((a, b) =>
      a.responseRate !== b.responseRate
        ? b.responseRate - a.responseRate
        : a.phone.localeCompare(b.phone)
    )
    .map((c) => c.phone);

  return [
    { phone: NATIONAL_EMERGENCY_PHONE, tollFree: true },
    ...[...new Set(hotlines)].map((phone) => ({ phone, tollFree: false })),
  ];
}
```

## Self-review notes

- **Coverage.** 192-first and toll-free flag → Task 1. Primary CTA everywhere → Tasks 2 and 3. Cost labelling → Tasks 2 and 3. 112 dropped → Task 3 Step 4.
- **Deliberate intermediate breakage.** Task 1 commits with typecheck errors in four screens; Tasks 2 and 3 clear them. The alternative is one commit spanning the type change and every consumer.
- **Rename over in-place change.** `dialOrder` → `dialTargets` is deliberate: reversing a chain's order while keeping its name would let a call site keep compiling with silently inverted meaning. The compiler now forces every site to be looked at.
- **Not in scope.** The server's `PrimaryPhone()` still returns the highest-`responseRate` hotline; nothing in the app consumes it for dialling any more, so no API change is required. The `response_rate` field remains the misnamed publication-order value it always was.
